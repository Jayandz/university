В pycharme для запуска высчитывания 2+3*4 я добавил функцию print()
в REPL результат отображается автоматически, потому что он это интерактивный режим
(вычисляет и сразу показывает). pycharm же просто выполняет код, ему нужна функция

в фрагменте 
`**course = "Python"
hours = 4 * 2
print(f"{course}: {hours} часов")**`
выражения: 'python', 4*2, f"{course}: {hours} часов", course и hours внутри print
инструкции: все три строки, они говорят интерпретатору что делать
литералы: 'python', 4, 2, :часов 
имена: course, hours, print

версия интерпретатора: Python 3.14.7

Присваивание, арифметическая операция:
`Assign(
         targets=[
            Name(id='course', ctx=Store())],
         value=Constant(value='Python')),
      Assign(
         targets=[
            Name(id='hours', ctx=Store())],
         value=BinOp(
            left=Constant(value=4),
            op=Mult(),
            right=Constant(value=2))),`

вызов принт: 
`value=Call(
            func=Name(id='print', ctx=Load()),
            args=[
               BinOp(
                  left=Constant(value=2),
                  op=Add(),
                  right=BinOp(
                     left=Constant(value=3),
                     op=Mult(),
                     right=Constant(value=4)))]))`

загрузка константы: 
`2           LOAD_CONST               1 ('Python')
              STORE_NAME               1 (course)`
вызов функции:
`1           LOAD_NAME                0 (print)`

Байткод CPython более высокоуровневый, чем машинный код, и рассчитан не на процессор, а на виртуальную машину Python. 
Процессор его не понимает и выполнить сам не может: байткод исполняет интерпретатор CPython, который читает его 
инструкции и выполняет соответствующие действия уже скомпилированным машинным кодом. Поэтому байткод не привязан к 
архитектуре процессора

# Задание 3

##Эксперимент A. int и арифметические операторы

/ это оператор обычного (true) деления, он всегда возвращает float, даже если числа делятся нацело (например 10 / 2 даст 5.0, а не 5). Это сделано специально, чтобы результат деления был предсказуемым и не зависел от того, поделилось нацело или нет
// это оператор целочисленного (floor) деления, он берет результат деления и округляет вниз до целого. Если оба операнда int, результат тоже будет int, тк питон не видит смысла делать его float. А если хотя бы один из операндов float (например 17.0 // 5), то и результат будет float, просто уже без дробной части
То есть разница не только в значении, а в том что / думает сколько получится при делении, а // думает сколько раз y целиком помещается в x

## Эксперимент B. Большие целые числа

В большинстве языков (C, Java и тд) int занимает фиксированный размер в памяти, например 32 или 64 бита. Из-за этого у него есть четкий предел значений (условно от -2^31 до 2^31-1 для 32 бит), и если число выходит за эти границы, происходит переполнение: число может "обнулиться" и начать считать заново с минимума, или вообще упасть с ошибкой, в зависимости от языка
В python int устроен по-другому, у него нет фиксированного размера и нет предела значений (кроме реального обьема памяти компьютера). Если число становится слишком большим, python сам под капотом выделяет под него больше памяти. Из-за этого можно спокойно посчитать что-то типа 2 ** 1000 и получить точный результат без переполнения, хотя это займет больше памяти и будет работать чуть медленнее, чем с обычным фиксированным int

## Эксперимент C. float

Обьяснение через двоичное представление:

Компьютер хранит float не в десятичной системе, а в двоичной. Проблема в том, что многие обычные десятичные дроби (0.1, 0.2, 0.3) невозможно точно представить в двоичном виде, точно так же как 1/3 нельзя точно записать в виде конечной десятичной дроби (0.333...). Поэтому 0.1 и 0.2 на самом деле хранятся с крошечной погрешностью, и когда их складывают, погрешности складываются тоже. В итоге result получается не ровно 0.3, а 0.3 плюс маленькая ошибка порядка 10^-17, что и подтверждает result - 0.3

### вывод: float нельзя сравнивать через == напрямую, тк из-за погрешностей представления даже правильные с точки зрения математики вычисления могут дать чуть-чуть другое число. Вместо этого нужно использовать math.isclose(a, b), которая сравнивает числа с небольшой допустимой погрешностью (по умолчанию относительной)


## Эксперимент D. bool, complex и явное преобразование типов

Почему bool("False") дает True:

bool() для строк смотрит только на одно: пустая строка или нет. Пустая строка "" всегда False, а вообще любая непустая строка, даже "False", "0" или "no", будет True, потому что как обьект она существует и не пустая. Python не разбирает смысл текста внутри строки, ему важен только сам факт что там что-то есть

## Контрольные вопросы
1. Результат обычного деления (/) всегда имеет тип float потому что так сделано специально в python 3, чтобы результат деления был предсказуемым и не зависел от того, поделилось нацело или нет. Если бы деление иногда возвращало int, а иногда float, в зависимости от чисел, это было бы неудобно и могло приводить к ошибкам в коде
2. int("42") это преобразование из строки, python парсит текст "42" и превращает его в число 42, при этом строка должна выглядеть как целое число, иначе будет ошибка. int(42.9) это преобразование из float, тут python не парсит текст, а просто отбрасывает дробную часть числа (не округляет, а именно обрезает), поэтому получится 42. То есть в первом случае это чтение числа из текста, а во втором - усечение уже существующего числа
3. Falsy значения из эксперимента D: bool(0) и bool(""), тк 0 это falsy среди чисел, а пустая строка "" это falsy среди строк. Все остальные значения (bool(-1), bool("False")) truthy, тк -1 это ненулевое число, а "False" это непустая строка

### Пояснение:
ord() возвращает числовой код символа в Unicode (кодовую точку), chr() делает обратное — по числу восстанавливает символ, поэтому chr(ord(symbol)) == symbol. encode("utf-8") превращает символ в последовательность байт по правилам кодировки utf-8, и для кириллицы это обычно 2 байта на символ (в отличие от латиницы, где 1 символ = 1 байт)

## Контрольные вопросы

1. len(symbol) считает количество символов (кодовых точек Unicode) в строке, а len(symbol.encode("utf-8")) считает количество байт после кодирования. Для латиницы это обычно совпадает (1 символ = 1 байт), а для кириллицы, эмодзи и других не-ASCII символов один символ может занимать 2, 3 или 4 байта в utf-8, поэтому числа расходятся
2. В записи text[start:stop:step] start это индекс, с которого начинается срез (включительно), stop это индекс, на котором срез заканчивается (не включая его самого), step это шаг, с которым берутся символы. Если step отрицательный, срез идет с конца в начало. Любой из трёх параметров можно опустить, тогда используется значение по умолчанию (начало строки, конец строки, шаг 1)
3. Строка считается неизменяемым объектом, потому что после создания её нельзя поменять "на месте" — нет способа изменить хоть один символ внутри уже существующей строки.
